16.3 Node selection: the basics

ch16-s3-1

16.3.1 Nodes, and the flags that select them

A node is any resource of the DAG: a model, a seed, a snapshot, a data test, a unit test, a source, an exposure, an analysis (and, in projects that use the dbt Semantic Layer, semantic models, metrics and saved queries). The way you tell a command which nodes to work on is called node selection (FR: sélection de nœuds).

FlagMeaning
--select (short: -s)The nodes to include. Several values separated by spaces.
--excludeThe nodes to remove from the selection.
--selector <name>Use a named selection from selectors.yml (Section 16.8).
--resource-type, --exclude-resource-typeKeep or remove whole resource types (Section 16.7).
--indirect-selectionWhich tests come with the selected nodes (Section 16.9).
--models / -mOld name of --select, still accepted. Do not use it in new code.

Without any selection flag, a command works on every node it can handle (dbt run on every model, dbt test on every test…), unless the project defines a default selector (Section 16.8). The selection flags exist on run, build, test, seed, snapshot, compile, show, ls, docs generate, source freshness and clone. dbt run-operation, dbt deps, dbt debug and dbt clean do not select nodes.

ch16-s3-2

16.3.2 dbt ls: your selection checker

dbt ls prints the nodes a selection matches. It never connects to the warehouse, so it is fast and safe. Use it before any run or build you are not sure about.

$ dbt ls --select fct_orders
22:27:31  Running with dbt=1.11.16
22:27:31  Registered adapter: duckdb=1.11.0
22:27:32  Found 14 models, 2 analyses, 1 seed, 14 data tests, 2 snapshots, 5 sources, 669 macros
jaffle_dbt.marts.fct_orders
ch16-c8 bash small

The first three lines are logs. The last line is the result, written as the node's fully qualified name (FQN): project name, folders inside models/, model name. The global flag -q (--quiet) hides the logs; we use it in the rest of the chapter to keep the outputs short.

tip

Write -q before the command name: dbt -q ls -s fct_orders. It is a global flag, and this position always works. You can also add --resource-type model to see only models: most examples below do this, because otherwise the tests of each model are listed too.

ch16-s3-3

16.3.3 How dbt reads a bare word

You can write fct_orders without saying which method to use. dbt then chooses a default method, with a simple rule (we read it in the dbt-core source code, file selector_spec.py):

  1. The value contains a slash / → method path: (models/staging).

  2. It ends with .sql, .py or .csv → method file: (customer_segments.py).

  3. Otherwise → method fqn:. It matches a node name (fct_orders), or a dotted path inside the project (staging.stripe, marts). It never matches sources: use source: for them.

$ dbt -q ls -s staging.stripe
jaffle_dbt.staging.stripe.stg_stripe__payments
jaffle_dbt.staging.stripe.not_null_stg_stripe__payments_payment_id
jaffle_dbt.staging.stripe.unique_stg_stripe__payments_payment_id

The shell eats your stars. On macOS, zsh tries to expand an unquoted * into file names before dbt sees it:

$ dbt ls -s stg_jaffle_shop__*
zsh: no matches found: stg_jaffle_shop__*

dbt was never started. Always quote a selection that contains *, ? or brackets: dbt ls -s "stg_jaffle_shop__*". Quoting a selection with commas or spaces is a good habit too.
