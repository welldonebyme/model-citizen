Lesson 4.4

NULL: the value that is not a value

Five customers have no email address. In the table, their email is NULLen français : valeur absente. NULL means unknown or missing. It is not zero, it is not an empty text '', it is "we do not know".

Analogy

Imagine a form where somebody did not answer the question "What is your age?". You cannot say the age is 0. You cannot say it is equal to the age of another person who also did not answer: you simply do not know either age. SQL reasons exactly like this.

IS NULL, not = NULL

The only correct test is is null or is not null. Run this query in the lab sheet.

SQL
select id, first_name, email
from jaffle_shop.customers
where email is null;
on the exam!

Exam trap

where email = null runs without any error, and returns zero rows. The comparison is unknown for every row, so no row is kept. A query that is wrong but does not fail is the most dangerous kind of bug.

Where you will meet this in dbt

dbt's built-in not_null data test (Chapter 18) is just a query like select * from my_model where my_column is null. If it returns rows, the test fails.
