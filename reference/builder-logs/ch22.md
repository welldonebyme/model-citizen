## Bug 9 explained: why DuckDB printed NOTHING for the typo
dbt-core 1.11.16 validates YAML files against JSON schemas, but ONLY when the adapter is bigquery, databricks, redshift or snowflake
(`_JSONSCHEMA_SUPPORTED_ADAPTERS` in dbt/jsonschemas/jsonschemas.py). On DuckDB this validation is skipped, so typos in keys and
'property moved to config' deprecations are silent. To see what a Snowflake user would see, the builder ran dbt parse in-process
with that validation forced on (helper script `parse_with_jsonschema.py`, builder tool only - not for students):

### The helper (builder only)

```bash
$ cat /private/tmp/claude-501/-Users-mac-Documents-Adnane/01c25d17-e9ca-4e1a-939f-b5b3904f7a5e/scratchpad/a1/bin/parse_with_jsonschema.py
```
```text
"""Run `dbt parse` in-process with dbt's YAML JSON-schema validation forced ON.
dbt-core 1.11 only runs these validations for bigquery/databricks/redshift/snowflake;
this shows what a user of those adapters would see. Usage: python parse_with_jsonschema.py [extra dbt args]"""
import sys
import dbt.jsonschemas.jsonschemas as js
js._can_run_validations = lambda: True
from dbt.cli.main import dbtRunner
res = dbtRunner().invoke(["parse", "--no-partial-parse"] + sys.argv[1:])
sys.exit(0 if res.success else 1)
```
